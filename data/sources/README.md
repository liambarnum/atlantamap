# Source exports

Raw data pulled from elsewhere, kept for reference. Nothing here is loaded by the app;
`data/beltline.geojson` and `data/access-points.geojson` are what it reads, and those
are generated by `tools/build-data.js`.

## `osm-historic-railway-relation-13048389.geojson`

Overpass export of OpenStreetMap relation
[13048389](https://www.openstreetmap.org/relation/13048389), exported 2026-08-08.

**Not used as the corridor**, for three reasons:

1. It is tagged `route=railway`, `historic=yes` — the historic Belt Line *railway*, not
   the BeltLine *trail*. Much of the trail sits on this rail bed, but the two are not
   the same line, and the relation includes rail alignments the trail never used.
2. Its own `description` tag reads `Incomplete!`, and it is: the geometry spans
   latitude 33.719–33.775, while the loop runs 33.711–33.822. Everything north of
   Ponce is missing — Piedmont Park, the Northeast Trail, Lindbergh, the Northwest
   Trail and Westside Park.
3. It arrives as 23 disconnected fragments totalling 10.7 miles of a 22-mile loop,
   with only 14 endpoint pairs close enough to join.

To get the trail itself, query the named trail ways rather than the railway relation:

```
[out:json][timeout:90];
(
  way["name"~"BeltLine",i]["highway"](33.68,-84.50,33.85,-84.32);
  relation["name"~"BeltLine",i]["route"~"bicycle|foot|hiking"](33.68,-84.50,33.85,-84.32);
);
out geom;
```

Run it at [overpass-turbo.eu](https://overpass-turbo.eu) and use **Export → GeoJSON**.
The BeltLine trails are mapped in OSM as `highway=path`/`footway`/`cycleway` ways named
things like "Atlanta BeltLine Eastside Trail", which that query picks up and the
railway relation does not.
